# 📞 Полный Мастер-План Рефакторинга и Тестирования Звонков Knock-Knock (Telegram-Style Call System)

## 📋 Обзор задачи и цели
Данный план определяет пошаговую инструкцию и эталонные критерии качества для цепочки агентов по разработке, редизайну и тестированию системы WebRTC-звонков в приложении Knock-Knock. 

Цель: Привести логику звонков к абсолютно устойчивому состоянию (конечный автомат FSM) и создать премиальный UI/UX в стиле Telegram / iOS Call UI с полной поддержкой открытых и анонимных (Zero-Knowledge) аккаунтов, а также режима переключения между параллельными звонками («Вторая линия»).

## 🛠️ ЭТАП 1: Agent `CallLogicArchitect` (Инженер Логики и FSM)

### Ответственность:
Переработка бизнес-слоя, хранилища состояния Zustand и WebSocket SSE обработчика для устранения двойных сетевых вызовов, зависаний и корректной обработки всех сценариев + режима «Вторая линия».

### Точные задачи:
1. **Файл `app/src/features/calls/store.ts`**:
   - Внедрить экшен `resetIncomingCallUI()`, который сбрасывает только локальный UI (`isIncoming: false`, `incomingRoomId: null`, `incomingCallLogId: null`) БЕЗ отправки сетевого API-запроса `updateCallStatus`.
   - Обновить `initiateCall`, `acceptCall`, `rejectCall`, `endCall` для гарантированного сохранения и передачи `callLogId`.
   - Добавить в стор состояние `isMutedRingtone: boolean` и экшен `toggleMuteRingtone()`.
   - **Режим «Вторая линия» (Call Waiting)**:
     - Добавить экшен `endAndAcceptCall()`, который корректно завершает текущий активный разговор (`endCall()`) и мгновенно переключается на входящий вызов второго абонента (`acceptCall()`).

2. **Файл `app/src/features/calls/hooks/useCallRealtime.ts`**:
   - При получении SSE-событий со статусом `ENDED`, `REJECTED`, `MISSED` вызывать `resetIncomingCallUI()` вместо `rejectCall()`, исключая повторные API-запросы.
   - **Обработка звонка во время разговора**:
     - Если пользователь уже находится в разговоре (`store.isActive === true`) и поступает новый входящий вызов `RINGING`, плашка оверлея «Входящий вызов (Вторая линия)» показывается поверх видеокомнаты со специальными экшенами («Отклонить» / «Завершить текущий и ответить»).

3. **Файл `app/src/features/calls/utils/ringtone.ts`**:
   - Обеспечить корректную работу `stopRingtone()` и `startRingtone()` при переключении состояния `isMutedRingtone`.

4. **Обработка открытых и закрытых (Zero-Knowledge) профилей**:
   - Если профиль анонимный/закрытый, гарантировать генерацию ZK-аватар заглушки (`🔒`) и подстановку зашифрованного имени из метаданных комнаты без раскрытия `userId`.

### Чек-лист проверки для `CallLogicArchitect`:
- [ ] Отсутствуют повторные API-запросы `updateCallStatus` при отмене звонка со стороны получателя.
- [ ] Функция «Завершить текущий и ответить» плавно переключает активную комнату на нового абонента.
- [ ] Входящий вызов на несколько вкладок одного пользователя при ответе на первой вкладке закрывается на остальных без ложного пропущенного.
- [ ] TypeScript компилируется без ошибок (`tsc --noEmit`).

## 🎨 ЭТАП 2: Agent `FrontDesignAgent` (Telegram UI/UX Дизайнер)

### Ответственность:
Верстка компонентов `IncomingCallAlert` и `CallRoom` в точном соответствии с дизайн-системой Knock-Knock и эстетикой Telegram / iOS Call UI.

### Точные задачи:
1. **Файл `IncomingCallAlert.module.css` и `IncomingCallAlert.tsx`**:
   - **Карточка**: Компактное плавающее модальное окно (`max-width: 420px`), скругление `24px` (`var(--radius-2xl)`), тонкая неоновая рамка (`var(--glass-border)`), темный космический фон `var(--bg-cosmos)` с радиальным градиентом.
   - **Радарные волны**: 3 слоя анимированных концентрических колец (Telegram Radar Waves) вокруг центрального аватара (`110px` × `110px`).
   - **Панель управления (Action Dock)**:
     - 🔴 **Отклонить**: Круглая красная кнопка `60px` × `60px` (`intent="error"`, `variant="solid"`), иконка `PhoneOff`, подпись под кнопкой.
     - 🟢 **Принять / Завершить текущий и ответить**: Круглая зеленая кнопка `60px` × `60px` (`intent="success"`, `variant="solid"`), иконка `PhoneIncoming` с пульсирующим свечением, подпись под кнопкой.
     - 🔇 **Без звука**: Круглая нейтральная кнопка `48px` × `48px` (`intent="neutral"`, `variant="subtle"`), иконка `VolumeX`, выключает рингтон без сброса звонка.
   - **Режим «Вторая линия»**: Бейдж 📞 «Вторая линия — Абонент ждёт ответа».
   - **Инкогнито балун**: Показ бейджа 🔒 «Инкогнито аккаунт» при закрытом профиле.

2. **Файл `CallRoom.module.css` и `CallRoom.tsx`**:
   - **Экран дозвона (Исходящий)**: Крупный аватар с 3-мя акцентными радарными волнами, статусом «Подключение...» / «Ожидание ответа...» и плавающей круглой кнопкой отмены `PhoneOff`.
   - **Экран видеосессии (Видеозвонок)**:
     - Поддержка мобильной сетки PIP (Picture-in-Picture `120px` × `160px` для собственного видео в углу, видео собеседника — на весь экран 9:16).
     - Кнопка разворота камеры (`FlipCamera`) для мобильных устройств.
     - Анимированная карточка при выключенной камера с пульсирующей аудиоэквалайзерной плашкой.

### Чек-лист проверки для `FrontDesignAgent`:
- [ ] Кнопки управления круглые (`60px` × `60px`), не растянуты, имеют понятные иконки и подписи.
- [ ] Использованы только CSS-переменные из `index.css` (никакого хардкода).
- [ ] Mobile-First верстка полностью адаптивна на экранах `375px` и `1280px`.
