# Инструкция по Разделению Dev и Prod Деплоя (Скрытие следов)

Для того чтобы скрыть историю разработки, черновики, комментарии и сохранить анонимность автора при релизе, мы используем паттерн "Два Репозитория".

## 📦 Текущий статус
- **Локальная папка**: твой рабочий проект на Mac.
- **Remote `origin`**: твой личный/приватный репозиторий GitHub, куда сохраняется вся история (dev).

## 🚀 План миграции Prod-релизов

### Шаг 1: Создание Анонимного Аккаунта
1. Включи VPN (желательно не российский IP).
2. Создай анонимную почту (например, на ProtonMail или Tuta).
3. Создай новый GitHub аккаунт на эту почту, используя имя проекта (например, `NemoApp` или `NemoLabs`).
4. В новом GitHub создай пустой **публичный** (или приватный, по желанию) репозиторий: `nemo-messenger`.

### Шаг 2: Настройка второго SSH-ключа
Чтобы GitHub не путал твой личный аккаунт и анонимный, создаем новый ключ:
```bash
ssh-keygen -t ed25519 -C "nemo.app@proton.me" -f ~/.ssh/id_nemo_github
```
Добавляем в `~/.ssh/config` алиас для этого аккаунта:
```text
Host github-nemo
  HostName github.com
  User git
  IdentityFile ~/.ssh/id_nemo_github
  IdentitiesOnly yes
```
*Не забудь добавить публичный ключ (`~/.ssh/id_nemo_github.pub`) в настройки нового GitHub аккаунта!*

### Шаг 3: Добавление Prod-Remote
В твоей локальной папке проекта мы добавляем вторую точку пуша (remote), назвав ее `prod`:
```bash
git remote add prod git@github-nemo:NemoLabs/nemo-messenger.git
```

### Шаг 4: Релиз (Squash & Push)
Когда приходит время релиза, и ты хочешь выложить код БЕЗ истории коммитов:

**Способ А (Squash push через отдельную ветку):**
```bash
git checkout --orphan release
git add -A
git commit -m "Initial release v1.0.0"
git push prod release:main --force
git checkout main
git branch -D release
```
*Что это делает: создает временную ветку без истории (orphan), делает один общий коммит всего текущего кода и отправляет его в анонимный репозиторий как единственный коммит, а затем удаляет временную ветку у тебя локально.*

### 🛡 Что важно помнить:
1. **Удаление секретов**: Перед "orphan" коммитом убедись, что файлы `.env`, приватные ключи, конфиги инфраструктуры с реальными IP-адресами надежно скрыты в `.gitignore`.
2. **Тотальный ребрендинг**: Убедись, что в коде не осталось путей вида `/Users/alexstone/...`, старых названий "knock-knock" и твой `Stonek79`.
