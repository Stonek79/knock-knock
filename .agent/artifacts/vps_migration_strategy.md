# Стратегия миграции на зарубежный VPS (Фаза 4)

Архитектура Zero-Knowledge требует не только сокрытия данных в БД (что мы уже сделали), но и защиты трафика, а также обхода возможных региональных блокировок (особенно для Web Push API от Google/Apple).

## Текущее состояние (Как работает сейчас)
1. База данных (PocketBase) и Push-шлюз (`push-gateway`) крутятся на **домашнем сервере в РФ**.
2. Используется **WireGuard VPN** (`wg0.conf`), через который NGINX на VPS проксирует трафик на домашний сервер (`10.50.0.2:8090`).
3. Контейнер `push-gateway` находится в одной docker-сети с `pocketbase` и вызывается по адресу `http://knock-knock-push:4000`. В результате пуши уходят в FCM/APNs с российского IP-адреса, что подвержено блокировкам и деанонимизации.

## Цель миграции (Целевое состояние)
1. Оставить PocketBase (и все физические данные) на домашнем сервере (РФ).
2. Вынести NGINX (Reverse Proxy), TURN-сервер для WebRTC и `push-gateway` на **зарубежный VPS**.
3. Заменить/Дополнить WireGuard на **Rathole** (устойчивый к DPI/ТСПУ Reverse Proxy-туннель) для проброса порта 8090 от домашнего сервера на VPS.

---

## План перехода (Сделать "как сейчас", но с выносом на VPS)

### Шаг 1: Перенос Push-Gateway
- Переместить директорию `infra/home/push-gateway/` в `infra/vps/push-gateway/`.
- Развернуть там `docker-compose` для пуш-шлюза. Сервис должен слушать внутренний интерфейс туннеля (например, `10.50.0.1:4000` в WG), чтобы не быть открытым всему интернету.
- В `infra/prod/docker-compose.yml` (на домашнем сервере) изменить:
  `PB_PUSH_GATEWAY_URL=http://10.50.0.1:4000` (вместо `knock-knock-push`).

### Шаг 2: Внедрение Rathole (Опционально/Вместо WireGuard)
> Согласно `task.md`, требуется использовать `rathole`. Он лучше обходит блокировки провайдеров.
- Создать `infra/vps/rathole/server.toml` (настройка сервера на VPS для приёма туннеля).
- Создать `infra/home/rathole/client.toml` (настройка клиента на домашнем сервере, который пробрасывает локальный `0.0.0.0:8090` на VPS).
- Интегрировать Rathole в `docker-compose` конфиги обеих машин.
- Если WireGuard остаётся для администрирования, Rathole будет использоваться сугубо для проксирования TCP трафика NGINX -> PocketBase и PocketBase -> Push-Gateway.

### Шаг 3: Конфигурация NGINX на VPS
- Обновить `infra/vps/nginx.api.conf`.
- Проксирование трафика (`proxy_pass`) должно идти либо на порт, открытый сервером `rathole`, либо через `10.50.0.2:8090` (как сейчас). При использовании Rathole NGINX будет проксировать на `localhost:8090` внутри VPS (Rathole свяжет его с домом).

### Шаг 4: Обход блокировок для WebRTC
- Проверить настройки `turnserver.conf` в `infra/vps`, чтобы звонки (LiveKit/WebRTC) ходили через зарубежный VPS и не сливали реальные IP-адреса клиентов.
