# Архитектура и План Реализации PWA & Offline (Nemo)

## 📌 Текущее состояние
В проекте уже заложен мощный фундамент для PWA:
- Интегрирован `vite-plugin-pwa` (в режиме `injectManifest`).
- Создан кастомный Service Worker (`app/src/sw.ts`), реализующий precaching (через Workbox).
- Реализована дешифрация E2E Push-уведомлений (Blind Push) прямо внутри Service Worker-а.
- Внедрен Dexie.js (IndexedDB) для оффлайн хранения медиа-файлов (v3).

## 🎯 Цели этапа
Сделать приложение полностью независимым от качества сети, обеспечив опыт, сопоставимый с нативными (iOS/Android) приложениями (Mobile-First).

---

## 📋 План реализации

### Этап 1: Доработка PWA Manifest и Установка
Сделать приложение привлекательным при установке на домашний экран:
1. **Расширение `manifest` в `vite.config.ts`**:
   - Добавить недостающие размеры иконок (192, 512, maskable).
   - Настроить `screenshots` для богатого окна установки (Rich Install UI).
   - Настроить `shortcuts` (быстрые действия при долгом тапе на иконку, например: "Новый чат").
2. **Собственный UI установки (A2HS)**:
   - Перехват события `beforeinstallprompt`.
   - Создание красивого компонента (баннера/модалки) с предложением установить приложение (вместо стандартного браузерного).

### Этап 2: Расширенное кэширование (Workbox Runtime Caching)
Текущий precache работает только для статики (JS/CSS/HTML). Нужно кэшировать запросы к API:
1. **Динамическое кэширование в `sw.ts`**:
   - Аватарки и публичные профили пользователей (`CacheFirst` или `StaleWhileRevalidate`).
   - Системные шрифты и внешние иконки (Google Fonts / CDN).
2. **Оффлайн-фоллбэк**:
   - Если пользователь переходит по ссылке без сети, и страницы нет в кэше — показывать красивую кастомную `/offline.html` (или компонент fallback).

### Этап 3: Offline-First UI (Индикация и Состояние)
Приложение должно четко коммуницировать статус сети:
1. **Хук `useNetworkStatus`**:
   - Отслеживание событий `online` и `offline`.
2. **Глобальный индикатор**:
   - Ненавязчивая плашка (в `ControlBar` или поверх чатов), сообщающая "Соединение разорвано" / "Ожидание сети..." и "Подключение восстановлено".
3. **PocketBase Reconnection**:
   - Обработка обрывов SSE (`pb.realtime`). Автоматический реконнект и подтягивание пропущенных сообщений при возвращении в сеть.

### Этап 4: Background Sync (Отложенная отправка)
Отправка сообщений без интернета:
1. **Очередь сообщений (Outbox)**:
   - Использование Dexie.js (добавить таблицу `outbox`) для сохранения исходящих сообщений, когда нет сети.
2. **Background Sync API**:
   - Регистрация события `sync` в сервис-воркере.
   - Как только сеть появляется, SW отправляет накопленные сообщения в PocketBase (если браузер поддерживает Background Sync).
   - Фоллбэк: если Background Sync не поддерживается, клиентская часть (UI) при событии `online` вычитывает `outbox` и сама отправляет сообщения.

### Этап 5: Оффлайн история сообщений (Опционально)
1. Синхронизация последних N сообщений в Dexie.js, чтобы при открытии чата без сети сразу показывалась локальная история переписки, а не пустой экран. (Это расширение функционала медиа-базы).

## 🛠 Технические требования
- Строгая типизация (`app/src/sw.ts` должен оставаться без `any`).
- Соответствие правилам проекта (без хардкода строк/пикселей).
- Использование UI-кита и дизайн-системы для оффлайн-плашек.
