# Гибридная S3 Инфраструктура (Nemo)

## 📌 Концепция
Отделяем «горячую» логику от «холодного» хранилища. 
- **VPS (Ninja)**: Отвечает за быструю отдачу статики (Web), мгновенный ответ API (Текст/БД) и видеозвонки (WebRTC).
- **Домашний сервер**: Отвечает только за физическое хранение тяжелых медиафайлов (картинки, видео, голос).

## 🏗 Архитектура узлов

### 1. Финский Сервер (Точка Входа)
- **Роль**: Защита от DPI блокировок и маршрутизация.
- **Инструменты**: iptables (DNAT/MASQUERADE).
- **Задачи**: Принимает трафик на 80, 443 (TCP) и 50000-60000 (UDP) и мгновенно перекидывает на Ninja VPS. Не хранит ничего.

### 2. Ninja VPS (Боевой сервер)
- **Роль**: Основной вычислительный узел приложения.
- **Инструменты**: 
  - Nginx (Раздает сбилженный фронтенд, терминирует SSL).
  - PocketBase Prod (БД SQLite с текстами, логинами, настройками).
  - LiveKit (Сервер звонков, принимает чистый UDP от Финна).
  - Push-Gateway (Отправка уведомлений в Apple/Google без риска блокировок).
  - FRP Server / frps (Ожидает подключения из дома для S3).

### 3. Домашний Сервер (Секретное Хранилище)
- **Роль**: Безопасный сейф для тяжелых данных и среда разработки.
- **Инструменты**:
  - MinIO (Легковесный S3 сервер для приема файлов).
  - FRP Client / frpc (Пробивает NAT и пробрасывает порт MinIO на Ninja VPS).
  - PocketBase Dev и Mailpit (Для локальной разработки).

## 🚀 Как работает маршрутизация медиафайлов
1. Пользователь отправляет картинку в чат.
2. Запрос прилетает на Ninja VPS в PocketBase Prod.
3. PocketBase настроен на использование S3. Вместо сохранения на диск VPS, он отправляет файл по S3 API на 127.0.0.1:9000 (локальный порт VPS, проброшенный через FRP).
4. Файл улетает по зашифрованному FRP-туннелю на домашний сервер в MinIO.
5. Запись в базе (текст) остается на VPS. Файл — дома.

## 🛡 Отказоустойчивость
Если дома пропадает интернет:
- Приложение продолжает работать, интерфейс грузится мгновенно.
- Звонки работают идеально (LiveKit на VPS).
- Текстовые сообщения отправляются и доставляются.
- **Ограничение**: Временно не отправляются и не загружаются старые медиафайлы до восстановления туннеля.
