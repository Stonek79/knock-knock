# 📞 План реализации WebRTC (Аудио/Видео звонки) для Knock-Knock (v2.0 Telegram-like)

## 1. Архитектурное видение (Zero-Knowledge, Mobile-First & Telegram-like UX)

Архитектура звонков строится по принципу **Zero-Knowledge (ZK)** и **Mobile-First**:
- Серверная инфраструктура **не знает** реальных имен участников и их сетевых IP-адресов.
- UI звонилки на 100% строится на **собственном UI-ките проекта** (`src/components/ui/`), полностью отказавшись от дефолтных UI-компонентов LiveKit (таких как `<VideoConference />`).
- **Telegram-like UX**: Строгий конечный автомат (State Machine), поддержка второй линии, плавные микроанимации (glassmorphism), PiP (Picture-in-Picture) для видеозвонков и прозрачное переключение аудио/видео.

### Инфраструктурный стек (`whoami.ninja`):
- **LiveKit Server (`whoami-livekit`)**: SFU-сервер, маршрутизирует UDP-пакеты, обернут Nginx-проксированием WSS (`wss://whoami.ninja/livekit/`).
- **Push & LiveKit Token Gateway (`whoami-push`)**: Внутренний микросервис для генерации JWT-токенов LiveKit.
- **PocketBase Backend (`whoami-pb`)**: Авторизатор, валидирует права, создает анонимные identity (`anon_${md5}`), логирует звонки в `call_logs` с зашифрованными метаданными и управляет сменой статусов (с блокировкой "мертвых" звонков).

## 2. Конечный автомат (State Machine) звонков

Вместо булевых флагов (`isActive`, `isIncoming`) `useCallStore` (Zustand) переходит на строгие сессии, что позволяет реализовать **вторую линию**:

*   **`activeSession`**: Текущий исходящий или принятый вызов.
    *   `status`: `INITIATING` -> `CALLING` -> `CONNECTING` -> `ACTIVE` -> `RECONNECTING`
    *   `type`: `'audio' | 'video'` (Критично для UI и запроса прав камеры)
    *   `isInitiator`: `boolean`
*   **`incomingSession`**: Входящий вызов (может работать параллельно с `activeSession`).
    *   `type`: `'audio' | 'video'`

### Транзиции (Переходы)
1. **Инициатор**: `IDLE` -> `INITIATING` (Запрос токена) -> `CALLING` (Гудки/Пульсация) -> (собеседник принял) -> `CONNECTING` -> `ACTIVE`.
2. **Получатель**: `IDLE` -> (SSE событие) -> появляется `incomingSession` (Входящий вызов).
3. **Принятие вызова**: `incomingSession` закрывается -> `activeSession` переходит в `INITIATING` -> `CONNECTING` (Установка соединения) -> `ACTIVE`.

## 3. Архитектура UI/UX (Аудио и Видео)

### 🎨 Кастомный LiveKit UI (Отказ от `<VideoConference />`)
Используются низкоуровневые хуки `@livekit/components-react` (`useTracks`, `useRemoteParticipants`, `useLocalParticipant`), а рендеринг строится на компонентах дизайн-системы Knock-Knock.

### 🎥 Видеозвонки и Picture-in-Picture (PiP)
*   **Ожидание ответа (CALLING/CONNECTING)**:
    *   *Для инициатора*: Если тип `video`, сразу запрашиваются права на камеру. Показывается размытое превью с фронтальной камеры, поверх которого выводится аватар собеседника и текст "Ожидание ответа...".
    *   *Для получателя*: Кнопка "Принять" сразу включает камеру (или предлагает выбор "С видео" / "Без видео").
*   **Активный звонок (ACTIVE)**:
    *   *Аудио*: Крупный аватар собеседника по центру, фоновое размытие, таймер звонка.
    *   *Видео*: Полноэкранное видео собеседника. Видео текущего пользователя отображается в плавающем окне (Picture-in-Picture) в правом нижнем углу экрана. Поддержка смены камер.

### 🎭 Обработка таймаутов и Вторая линия
*   **Четкое разделение отклонений**: 
    *   Сброс кнопкой (красная трубка) = статус `REJECTED`.
    *   Отсутствие ответа в течение 45 сек = статус `MISSED`.
*   **Вторая линия**: Если `activeSession` активна, входящий звонок сохраняется в `incomingSession`, вызывая компактную плашку сверху (Z-index выше звонка) с возможностью "Сбросить" или "Завершить текущий и принять новый".

## 5. Критерии приемки и качество
- [ ] TypeScript: Полное покрытие типов, никаких `any`. Строгая типизация `ActiveCallStatus`.
- [ ] Biome: 0 ошибок форматирования и линтинга.
- [ ] Безопасность: Полное отсутствие ложных соединений или переадресаций на "исходящий" при принятии.
- [ ] UI/UX: Адаптивность Mobile-First, корректная работа PiP и размытия (backdrop-filter) на iOS Safari / Android Chrome.
