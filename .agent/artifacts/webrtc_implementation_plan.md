# План реализации WebRTC (Аудио/Видео звонки) для Knock-Knock

## 1. Архитектурное видение (Zero-Knowledge)

Архитектура звонков строится так, чтобы серверная инфраструктура **не знала** реальных имен звонящих и не могла прослушивать разговоры, а сам медиа-трафик легко обходил блокировки (DPI).

- **LiveKit Server (SFU)**: Разворачивается на публичном VPS (`149.33.42.8`). Это решает фундаментальную проблему WebRTC за NAT/VPN. Сервер маршрутизирует зашифрованный (DTLS-SRTP) медиа-трафик по UDP (порты 50000-60000). У LiveKit нет доступа к БД PocketBase, он ничего не знает о пользователях.
- **Service Gateway (VPS)**: Наш текущий `push-gateway` (Node.js) расширяется эндпоинтом для генерации `LiveKit JWT` токенов. В PocketBase (Goja) нет библиотеки для JWT, поэтому генерация токенов делегируется этому внутреннему сервису.
- **PocketBase (Home Server)**: Выступает в роли авторизатора. Пользователь просит токен для звонка -> PB проверяет права на `room` -> PB делает внутренний HTTP запрос к Service Gateway -> Отдает токен клиенту.
- **Zero-Knowledge Identity**: В LiveKit-токен (в поля `identity` и `name`) зашиваются **исключительно UUID** пользователей. На клиенте эти UUID "на лету" сопоставляются с именами из `Key Vault` или публичными профилями.

## 2. Пошаговый план внедрения

### Этап 1: Инфраструктура на VPS (LiveKit Server)
1. **LiveKit Server**:
   - Добавить сервис `livekit` в `infra/vps_new/docker-compose.yml`.
   - Создать конфигурацию `livekit.yaml` с надежными `API_KEY` и `API_SECRET`.
   - Настроить Nginx (`api.whoami.ninja.conf`) для проксирования WebSocket трафика (сигнализация LiveKit) к `livekit` сервису по определенному пути (например, `/livekit`).
   - Открыть UDP-порты `50000-60000` в фаерволе VPS (обязательно для WebRTC).
2. **Обновление Push-Gateway (Node.js)**:
   - Установить пакет `livekit-server-sdk` в проект гейтвея (`infra/vps_new/push-gateway`).
   - Добавить POST эндпоинт `/api/livekit-token`, который принимает `roomName`, `participantIdentity` (UUID) и генерирует подписанный JWT.

### Этап 2: Бэкенд на Домашнем Сервере (PocketBase)
1. **Выдача токенов (`pb_hooks`)**:
   - Создать защищенный эндпоинт `POST /api/calls/token` в `pb_hooks/calls.pb.js`.
   - Логика: проверить, состоит ли `@request.auth.id` в запрошенной комнате. Если да — запросить JWT у Push Gateway (напрямую по внутренней сети) и отдать фронтенду.
2. **Логи звонков (`call_logs`)**:
   - Запись о начале звонка создается со статусом `ringing`.
   - Поле `encrypted_metadata` шифруется ключом комнаты (на фронте) и содержит список реальных участников звонка.
   - По окончании звонка (поимка webhook'а от LiveKit или отбивка от клиента) обновляем `status`, `duration_sec`, `ended_at`.

### Этап 3: Фронтенд (LiveKit UI и Логика)
1. **Подготовка и Зависимости**:
   - Установить `@livekit/components-react`, `@livekit/components-core`, `livekit-client`.
2. **Сигнализация вызова (Ringing)**:
   - Инициатор создает запись в `call_logs` (статус `ringing`).
   - Бэкенд рассылает Blind Push и SSE `event: call_incoming` всем участникам комнаты.
   - Фронтенд реагирует на событие, открывая "Экран входящего вызова" поверх приложения с кнопками "Принять" / "Отклонить".
3. **Менеджмент состояния (`useCallStore.ts`)**:
   - Реализовать Zustand-хранилище с состояниями: `idle`, `ringing`, `connecting`, `in-call`.
4. **Zero-Knowledge Интерфейс звонка (`CallRoom.tsx`)**:
   - Использовать готовые UI компоненты LiveKit (`<VideoConference />`, `<ControlBar />`).
   - Использовать кастомный маппер для участников (хук `useParticipants`), который перехватывает UUID из LiveKit (`participant.identity`) и подменяет их на расшифрованные имена и аватары из локального `ContactStore` / `ProfileCryptoService`.

### Этап 4: UI/UX и Premium Дизайн
- **Экран вызова**: Стильный оверлей (glassmorphism эффект) поверх чата. Анимация пульсации при входящем/исходящем звонке.
- **В звонке**: Удобное переключение камеры и микрофона, возможность сворачивания видео в плавающее окно (PiP) для продолжения переписки.
- Мобильная адаптивность (Mobile First) — звонилка должна идеально смотреться на смартфонах.
