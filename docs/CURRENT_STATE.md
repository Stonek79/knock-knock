# Текущее состояние Nemo

> Единственный актуальный снимок развернутой архитектуры и согласованных
> требований. Реализация одноразового режима ещё не завершена — разделы с его
> правилами являются целевым контрактом, а не заявлением о готовой функции.
> Старые планы и
> пошаговые инструкции ниже могут содержать исторические решения и не являются
> источником истины.

## Размещение сервисов сейчас

### Домашний сервер

- `whoami-pb-dev` — Dev PocketBase, порт хоста `9090`;
- `whoami-pb` — текущий Prod PocketBase, порт хоста `8090`;
- `nemo-minio` — MinIO, API и консоль доступны только через `127.0.0.1`;
- `whoami-frpc` — исходящий FRP-клиент;
- Mailpit — только для разработки.

Dev и текущий Prod используют отдельные PocketBase-хранилища и отдельные
MinIO bucket’ы (`nemo-dev` и `nemo-prod`) с разными service account.

### VPS

- Nginx — единственная публичная HTTP(S)-точка входа;
- FRP server — принимает туннель от дома;
- LiveKit — звонки и WebRTC media;
- Push gateway — серверная отправка push и выдача LiveKit-токенов.

Перенос Prod PocketBase на VPS — будущий этап, а не текущая deployed-схема.
Маршрут VPS `127.0.0.1:19000` → домашний MinIO уже запущен и проверен HTTP
health request. Сейчас он не делает Prod PocketBase на VPS развернутым.

## Три режима профиля

### Открытый профиль

Профиль доступен для поиска и приглашений. Общение и группы открытого уровня
состоят только из открытых профилей.

### Закрытый профиль

Профиль не имеет внешнего идентификатора. Внутри приложения используется
регистрационный ID и псевдоним. Общение разрешено только с закрытыми профилями.

### Одноразовый профиль и секретная комната

Одноразовый профиль создаётся только для персонального приглашения в секретную
комнату. Приглашение одноразовое, персональное и имеет TTL.

Правила текущего решения:

- reconnect grace period — 2 минуты;
- отдельные устройства для одного одноразового профиля не поддерживаются;
- участник может выйти сам, не уничтожая комнату для остальных;
- закрытие комнаты создателем уничтожает комнату для всех;
- при выходе участника уничтожаются его временные ключи и локальные данные;
- если участник не вернулся за 2 минуты, его локальная сессия считается закрытой;
- клиент хранит локальный deadline/epoch и при следующем запуске самостоятельно
  очищает истёкшую сессию; постоянная серверная команда очистки не требуется;
- сообщение, файл и ключи одноразовой комнаты не сохраняются в обычном
  PocketBase/MinIO-контуре;
- медиа одноразовой комнаты живут только в памяти устройства и уничтожаются при
  выходе, закрытии комнаты или истечении reconnect-периода;
- push содержит только нейтральный сигнал без текста, имени комнаты и состава
  участников;
- одноразовые данные не включаются в резервные копии.

Существующий код с названиями `isPrivate`/`isEphemeral` не реализует этот
контракт: он использует обычные PocketBase/MinIO и не должен считаться
прототипом готового одноразового режима.

Нельзя технически гарантировать удаление скриншотов, экспортированных ключей,
данных отключенного устройства или сетевых метаданных провайдера. Реализация
должна гарантировать уничтожение серверных временных данных, ключей и локальных
кэшей, которыми управляет приложение.

## Медиа

Для постоянных профилей приложение шифрует медиа на клиенте до отправки в
PocketBase. PocketBase хранит запись и передает файл в соответствующий MinIO
bucket через S3-compatible storage. Dev и Prod никогда не используют общий
bucket или общий service account.

Одноразовые медиа идут по отдельному runtime-пути и не должны вызываться через
обычную коллекцию `media` или попадать в MinIO.
