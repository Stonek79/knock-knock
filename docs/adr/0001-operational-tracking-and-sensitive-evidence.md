# ADR-0001 — Операционные задачи и чувствительные доказательства

**Статус:** Принято  
**Дата:** 2026-08-12

## Контекст

Nemo обрабатывает сообщения, ключи, приглашения, push-подписки и другие данные,
которые нельзя распространять через рабочие артефакты. При этом долгоживущим
изменениям нужны понятные scope, критерии приёмки и след решения.

## Решение

GitHub Issues не являются обязательным трекером Nemo. При их использовании они
содержат только минимальные операционные метаданные: безопасный заголовок,
scope, приоритет, риск и критерии приёмки. Секреты, токены, invite-ссылки,
plaintext, чувствительные идентификаторы, полные endpoints, HAR, сырые логи,
скриншоты с пользовательскими данными и экспортированные данные запрещены в
Issues, комментариях, вложениях, Git и документации. Чувствительная проверка
фиксируется только redacted summary или результатом pass/fail без артефакта.

Долгосрочные архитектурные решения записываются в `docs/adr/`, если они трудно
обратимы, неочевидны без контекста и выбраны из реальных альтернатив. ADR не
заменяет task/specification, audit, очередь или журнал диагностики.

## Последствия

Операционная координация остаётся возможной без превращения GitHub в хранилище
чувствительных данных. Диагностические артефакты должны быть минимальными и
redacted; при невозможности этого работа останавливается до появления
разрешённого безопасного способа воспроизведения.
