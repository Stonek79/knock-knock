# ADR-0002 — Маркер тестовых данных и разделение окружений

**Статус:** Принято  
**Дата:** 2026-08-12

## Контекст

Dev и Prod Nemo используют разные PocketBase data directories и разные MinIO
bucket/service account. Это предотвращает смешение данных между окружениями,
но не отличает тестовые записи от постоянных Dev/Staging-данных внутри одной
базы.

Интеграционный cleanup удаляет записи только по `is_test = true`. Поэтому
одного разделения окружений недостаточно для безопасной и повторяемой очистки:
без маркера тест может удалить сиды или данные разработчиков.

## Решение

- Сохранять `is_test` в общей PocketBase-схеме для коллекций, которые участвуют
  в disposable integration setup.
- Использовать `is_test` только как операционный маркер тестового контура, а не
  как механизм изоляции Dev/Prod и не как признак доверия или авторизации.
- В приложении по умолчанию записывать `is_test = false`; тестовые seed/fixture
  явно записывают `true`.
- Очистку разрешать только при одновременном явном флаге и URL из allowlist
  локальных test/staging-контуров. Наличие `is_test` не является достаточным
  основанием для включения cleanup на Prod.
- Запретить клиенту произвольно устанавливать или менять `is_test`: значение
  для тестовых записей задаётся серверным seed/admin-контуром. Это правило
  реализовано в `infra/home/pb_hooks/security.pb.js`; superuser seed-контур
  может создавать и обновлять тестовые записи, обычный пользователь — нет.

## Альтернативы

1. Удалить `is_test` и полагаться только на разные базы. Это не позволяет
   безопасно отличать тестовые данные от Dev-данных и ухудшает cleanup.
2. Оставить только `is_test` без разделения окружений. Это небезопасно: ошибка
   фильтра или флага может затронуть Prod.
3. Принятое решение: два независимых барьера — отдельная среда и явная
   маркировка disposable-данных.

## Последствия

`is_test` остаётся необходимым для текущего integration cleanup, но не является
release/security boundary. Hook-защита проверена синтаксически; перед release
нужен runtime-негативный тест на staging с обычной пользовательской сессией.
